# v0.5.3 engineering plan

Status: active

Web App Security Skill v0.5.3 reduces adoption friction and review noise without widening active
network behavior or inflating the detector's claims. It adds npm/npx and Claude Code plugin
distribution, publishes current limitations, introduces bounded Git diff scopes, and makes the
built-in pattern contract reproducibly measurable. MCP and broader rule work receive an explicit
decision record rather than an untested implementation.

## Non-negotiable boundaries

1. `npx` and the Claude plugin must invoke the same repository runtime and skill instructions; no
   copied rule implementation or divergent skill body is allowed.
2. `--since` and `--staged` reduce output, not evidence standards. Changed-file parse failures and
   relevant global coverage failures remain visible and fail closed.
3. Diff-scoped runs cannot be used for baseline/retest lifecycle claims. v0.5.3 supports built-in
   source rules only in diff mode; external adapter diff semantics remain out of scope.
4. `--staged` audits an isolated Git index snapshot. `--since <commit>` audits the current working
   tree against an immutable resolved base commit; untracked files are not silently treated as part
   of that Git diff.
5. The ground-truth benchmark measures the planted positive/negative contract for 20 built-in risk
   rules and 2 evidence-integrity rules. It is not a production-vulnerability precision, recall or
   exploitability claim.
6. MCP and rule expansion remain design decisions in this release. No server, parser dependency,
   network service or new detection rule ships without a separate evidence contract.
7. Existing passive defaults, authorization gates, evidence states, report v3 compatibility,
   signed release assets and guarded `v1` promotion remain unchanged.

## Acceptance criteria

### Distribution

- `npm pack` contains the CLI runtime, rules, required schemas and references, while excluding test,
  launch/adoption working notes and generated demo media.
- Installing the packed tarball into an isolated prefix and running
  `npx web-app-security-skill audit <fixture>` produces a v3 report without using repository files.
- `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` pass the installed Claude Code
  validator. A temporary Claude configuration can add the local marketplace and install the plugin;
  the cached plugin exposes the repository-root single `SKILL.md`.
- The public command combines marketplace registration and plugin installation on one shell line,
  while also showing the two explicit Claude slash commands for users already in a session.

### Known limitations

- A root `KNOWN_LIMITATIONS.md` distinguishes current detector limits, expected false-positive
  classes, unsupported diff cases and resolved regressions.
- Every current limitation says what users may observe, what the tool does, and what evidence or
  manual review is still required. Fixed v0.5.2 bugs are historical regressions, not current issues.

### Incremental source audit

- `--since <ref>` resolves the ref to a commit and records that immutable commit in report scope.
- `--staged` scans an index snapshot, including staged additions and excluding unstaged content.
- Findings are retained only when their reported location intersects an added line. Path-only
  findings are retained for a changed file, and dependency-lockfile findings are retained when a
  relevant manifest, workspace file or lockfile changed.
- Pure deletions and pure renames do not replay unrelated findings. Changed-file coverage failures
  and global traversal incompleteness remain visible.
- Invalid refs, non-Git projects, conflicting modes, external adapters and baseline/retest use exit
  `2` before writing evidence.
- Reports identify the selection mode, resolved base, snapshot kind, changed-file/line counts and
  limits. A diff-clean report explicitly does not establish whole-repository safety.

### Benchmark

- One command regenerates JSON and Markdown results from committed fixtures and stable rule metadata.
- The runner reports TP, FP and FN counts separately for risk and evidence-integrity rules, validates
  expected evidence states, and exits non-zero on a planted missing positive or unexpected negative.
- CI checks committed benchmark bytes. README wording calls it a pattern-contract benchmark and keeps
  the five ordinary-project manual review separate.

### Release

- Version, changelog, npm/plugin metadata, READMEs, roadmap, capability/public surfaces, release note
  and release state agree on v0.5.3 without claiming MCP or broader vulnerability recall.
- Focused tests run during implementation; the complete repository gate runs once at candidate time.
- GitHub Release assets are byte-reproducible, signed, attested and publicly reverified.
- The npm package is installed and executed from the public registry after publication. If initial
  npm ownership requires interactive account authentication, release publication pauses at that
  external boundary without weakening package verification.
- The verified installer receives immutable v0.5.3 asset digests. Signed `v1` moves with a guarded
  lease only after immutable consumers pass, followed by the public `v1` consumer workflow.

## Phase record

### P0 - completed

- The npm registry returned `E404` for `web-app-security-skill`, so the unscoped name was available at
  contract-freeze time. The local machine was not authenticated to npm; no registry state changed.
- Claude Code documentation dated 2026-08-13 states that a plugin with exactly one skill may keep
  `SKILL.md` at the plugin root. The installed Claude CLI is 2.1.284 and provides `plugin validate`,
  marketplace add and plugin install commands.
- The existing npm `bin` already points at `scripts/webapp-security.mjs`. v0.5.3 will add the package-
  named executable while preserving `webapp-security` for conventional installs.
- The report v3 lifecycle treats absent current findings as fixed during baseline comparison;
  therefore diff selection is intentionally audit-only and is applied before report initialization.
- Existing stable fixtures already cover all 22 built-in rules with positive and negative examples.
  The benchmark will execute those fixtures and publish machine-readable outcomes instead of adding
  a second corpus.

### P1 - completed

- The explicit npm file allowlist packs 135 entries (318,458 bytes packed; 1,205,972 bytes
  unpacked) and excludes engineering plans, adoption working notes, tests and generated demo media.
- An isolated install from the packed tarball ran both the package-named `npx` executable and a
  real source audit without reading repository-only files.
- Claude Code 2.1.284 validated both manifests. A temporary `CLAUDE_CONFIG_DIR` added the local
  marketplace, installed `web-app-security-skill@web-app-security`, and listed the installed plugin
  without changing the user's normal Claude configuration.
- `KNOWN_LIMITATIONS.md` publishes current detector boundaries, expected false-positive classes,
  diff-scope limits and resolved v0.5.2 regressions. The distribution contract checks that it ships
  through npm and the Claude plugin.

### P2 - completed

- `--since <ref>` resolves and records an immutable commit, scans the working tree with full source
  context, filters exact-location findings to added lines, and records the count of excluded
  untracked files.
- `--staged` exports the Git index to an isolated temporary snapshot. A regression stages one
  vulnerable condition and leaves a different condition unstaged, proving the report reads the
  index and excludes working-tree-only content.
- Path-level environment findings follow materially changed files. Missing-lockfile findings remain
  visible when a relevant manifest, workspace definition or ancestor lockfile changes. Changed-file
  parser failures and global traversal limits remain fail-closed.
- Focused regressions cover old-versus-added findings, new inputs, content-identical renames,
  lockfile deletion, malformed changed source, clean index state and refusal of invalid refs,
  non-Git input, baseline/retest combinations and external adapters.
- Reports record mode, base commit, snapshot kind, changed-file count, added-line count and excluded
  untracked count. Markdown, HTML and limitations state that a clean diff does not establish
  whole-repository safety.

### P3 - completed

- `npm run benchmark:ground-truth` regenerates committed JSON and Markdown from the existing stable
  corpus and the same bounded inspectors used by the product. `--check` compares exact bytes in CI.
- The 20 risk-rule cases report TP=20, FN=0, TN=20 and FP=0. The two evidence-integrity cases report
  TP=2, FN=0, TN=2 and FP=0, with no evidence-state mismatch.
- Planting one missing positive produces one FN and a nonzero validation result. Planting a safe-
  neighbour match produces one FP and a nonzero validation result.
- Every benchmark surface labels the result as a synthetic planted pattern contract and rejects a
  production-vulnerability precision, recall, reachability or exploitability interpretation.

### P4 - completed

- The architecture decision keeps MCP and stable rule-count expansion outside v0.5.3. It defines
  demand, permission, transport, schema, runtime-reuse, distribution and regression gates before a
  local stdio MCP implementation can enter a release.
- Every future stable rule must supply threat/action scope, taxonomy, evidence boundary, planted
  positive/negative fixtures, fail-closed behavior, explanation/retest text, ordinary-code false-
  positive review and deterministic bounded output.
- `ROADMAP.md` separates these future gates from shipped v0.5.3 work. `KNOWN_LIMITATIONS.md` states
  the current lack of MCP/rule expansion and the exact interpretation limit of benchmark counts.
