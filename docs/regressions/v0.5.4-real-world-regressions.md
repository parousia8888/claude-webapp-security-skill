## Evidence boundaries

### The main risk summary rendered JavaScript objects

- Case: `v3-summary-object-coercion`
- Source: `historical_regression`; `docs/adoption/regressions.json#v3-summary-object-coercion`
- Observed failure: A v3 report with risk-domain state totals rendered [object Object] in Markdown and HTML.
- Current evidence: `{"findingCount":1,"markdownNumericSummary":true,"htmlNumericSummary":true,"objectCoercionObserved":false}`
- Remaining boundary: Golden rendering tests protect the current fixture shapes; they do not prove every future presentation is understandable.

### A pnpm workspace could receive a false confirmed lockfile absence

- Case: `pnpm-workspace-lockfile-evidence`
- Source: `historical_regression`; `docs/adoption/regressions.json#pnpm-workspace-lockfile-evidence`
- Observed failure: A root pnpm-lock.yaml and pnpm-workspace.yaml covering apps/* still allowed a child package.json to be reported as confirmed missing-lockfile evidence.
- Current evidence: `{"coveredPackage":"apps/web/package.json","coveredPackageFindingCount":0,"outsidePackage":"tools/outside/package.json","outsidePackageState":"confirmed"}`
- Remaining boundary: The parser supports the documented bounded subset and is not a general YAML evaluator.

### Nested JS/TS templates could make a whole file partial

- Case: `nested-template-coverage`
- Source: `historical_regression`; `docs/adoption/regressions.json#nested-template-coverage`
- Observed failure: A nested template such as const html = `${`</b>`}</div>` produced unterminated_string_literal and stopped normal source-rule coverage for that file.
- Current evidence: `{"sourcePath":"src/server.ts","browserSinkCoverage":"completed","incompleteEvidenceFindingCount":0}`
- Remaining boundary: The tokenizer is still bounded and reports unsupported syntax as incomplete evidence rather than silently passing it.

### A path-only rename could make a retest exit successfully

- Case: `path-rename-retest`
- Source: `historical_regression`; `docs/adoption/regressions.json#path-rename-retest`
- Observed failure: Renaming a file without removing its condition produced one fixed and one new finding, allowing the compatible baseline gate to exit successfully.
- Current evidence: `{"priorPath":"src/old.js","currentPath":"src/renamed.js","baselineState":"unchanged","reasonCode":"condition_moved","fixedCount":0,"newCount":0}`
- Remaining boundary: condition_moved means an equivalent condition exists elsewhere; it does not prove historical identity or that a git move caused it.

### Numeric SVG innerHTML remains a review-visible expected match

- Case: `numeric-svg-innerhtml-review`
- Source: `external_review_minimized`; `KNOWN_LIMITATIONS.md#recurring-expected-matches`
- Observed failure: A numeric-only SVG string assembled with innerHTML matched the intentionally broad DOM-sink rule.
- Current evidence: `{"sourcePath":"src/charts.ts","ruleId":"browser-html-injection-sink","evidenceState":"suspected","manualClassification":"expected_benign_match","requiredClosure":"Confirm that every interpolated value remains numeric and no untrusted markup reaches the sink.","suppressionApplied":false}`
- Remaining boundary: This fixture is benign only because its constructed values are numeric. The detector does not trace arbitrary input or prove other innerHTML assignments safe.
