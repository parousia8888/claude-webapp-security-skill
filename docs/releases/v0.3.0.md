# v0.3.0 release evidence

## Scope

Productization and trust signals around the existing security methodology: a unified CLI and
installer, passive-by-default GitHub Action, deterministic before/after demo, release provenance,
project governance and five immutable-commit source case studies.

The public identity is **Web App Security Skill**: repository `web-app-security-skill`, Skill ID
`web-app-security`, CLI `webapp-security`, and matching Action/release/SBOM artifact names. Existing
`webapp-security-hardening` local installs are detected and backed up during forced migration.

## Reproduced regressions

- Passive crawl mode never requests `/.env`; active probes reject execution before network access
  unless `--acknowledge-authorization` is present.
- Active edge rate-limit verification likewise requires explicit authorization acknowledgement.
- The Action rejects a missing/false authorization input and preserves the audit exit code.
- Demo result is fixed at before `13 high / 6 medium`, after `0 high / 0 medium`, with JSON,
  Markdown and patch evidence.
- Installer preflights all selected destinations, prevents partial installation, backs up replaced
  content and installs Claude Code, Codex and ordinary CLI surfaces.
- Project discovery creates a private, versioned, network-free scope without reading secret files;
  deterministic source findings render from one validated schema to JSON, Markdown, escaped HTML,
  SARIF and JUnit. Baseline tests cover new, fixed, unchanged and regressed states, and patch output
  is never applied automatically.
- Generated SPDX document is schema-smoke-tested, version-aligned and reproducible under
  `SOURCE_DATE_EPOCH`.
- Crawler product identity, strict IP parsing, TLS policy, certificate validation and network
  failure semantics retain their earlier regressions.

## Verification commands

```bash
npm run check
npm run demo -- --out ./demo-output
python3 /path/to/skill-creator/scripts/quick_validate.py .
```

The release workflow additionally verifies tag/version/evidence alignment before producing the
source archive, SBOM, checksums and provenance attestation.

## Case-study evidence

The corpus fixes Juice Shop, NodeGoat, DVWA, Uptime Kuma and Mealie to immutable commits. No hosted
instance was probed. Intentional training vulnerabilities are separated from two production-project
leads that were closed or left unknown after source-to-boundary tracing.

## What this does not prove

The CLI is not a general SAST engine and the case studies are not a precision benchmark. No
authenticated third-party application, production cloud account or upstream live deployment was
actively tested. Release checksums and attestations prove artifact identity and build origin, not
the correctness of every security conclusion.
